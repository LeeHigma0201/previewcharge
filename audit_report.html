Critical Lookahead Bias

1. trainer_patterns.py queries future data
check_trainer_patterns() queries ALL trainer entries without date filtering. Compare with compute_jockey_trainer_features() which correctly uses Race.race_date < race_date. If trainer_patterns is ever used in model training or feature computation, it will leak future results into predictions.

Fix: Add .join(Race).filter(Race.race_date < entry.race.race_date) to the query at line 36.
src/longshot/trainer_patterns.py:36-41

Warning Code Quality Issues (5)

2. Duplicate UNIT_COSTS constants
UNIT_COSTS is defined separately in both exotic_engine.py:126 and ranked_exotics.py:43 with identical values. If one changes, the other won't. Should be a single constant imported from kelly.py or a shared config.
src/betting/exotic_engine.py:126 & src/betting/ranked_exotics.py:43
3. Inconsistent takeout defaults across modules
Takeout rates default to different values in different functions:
• signals.py: 0.17 (win pool)
• kelly.py: 0.22 (exotic pool)
• value.py kelly_fraction(): 0.0 (!)
• config/settings.py: 0.17 win / 0.22 exotic
The 0.0 default in value.py is misleading — calling kelly_fraction() without explicit takeout overstates the Kelly stake by 17-22%.
src/longshot/value.py:23 vs config/settings.py:26
4. N+1 query in track_bias_feature (per-entry DB hit)
compute_track_bias_feature() runs a session.query(TrackBias) for every entry in a race. For an 8-horse field, that's 8 identical queries returning the same row. Should be cached at race level inside compute_race_features() and passed down, like _compute_pace_scenario() already does.
src/features/core.py:428-467 (called from line 487)
5. No database migration system for new tables
TrackBias and OddsSnapshot were added to models.py. Base.metadata.create_all() creates them in new DBs, but existing horsegpt.db databases won't get the new tables automatically. Need either Alembic or a one-time CREATE TABLE IF NOT EXISTS in the init script.
src/data/models.py (TrackBias:194, OddsSnapshot:217)
6. New Gap modules not wired into CLI or dashboard
The 8 new features (entropy, horizontal sequencer, EVPD, capable longshot filter, track bias, live odds) are implemented and tested but not yet integrated into:
• cli.py (no CLI commands for entropy, horizontal, EVPD)
• dashboard/ (no Streamlit pages for new modules)
• exotic_engine.py (doesn't use capable filter or EVPD)
They exist as standalone importable modules awaiting wiring.
src/models/horizontal.py, src/models/entropy.py, src/longshot/value.py (compute_exotic_evpd)

Info Observations (8)

7. check_trainer_patterns() is never called
trainer_patterns.py defines check_trainer_patterns() but it's not imported or called from any other file in the codebase. It's dead code. check_pace_signals() in pace_scenarios.py is similarly uncalled from the signal pipeline (only estimate_pace_impact is used by the dashboard).
src/longshot/trainer_patterns.py:19 & src/longshot/pace_scenarios.py:48
8. Stub modules: gnn_pace.py, neural_net.py, interactions.py
Three modules raise NotImplementedError or return unchanged data:
• gnn_pace.py: GATv2Conv architecture documented but not implemented (Phase 4)
• neural_net.py: 44-line stub
• interactions.py: Returns input unchanged (Phase 2 placeholder)
src/models/gnn_pace.py, src/models/neural_net.py, src/features/interactions.py
9. Missing statsmodels dependency breaks test_logistic.py
statsmodels is not installed in the current Python 3.14 environment. test_logistic.py fails to collect with ModuleNotFoundError: No module named 'statsmodels'. The Benter logistic model itself also cannot be used without it.
src/models/logistic.py:24 (import statsmodels.api)
10. EquibaseLiveOdds.fetch_odds() returns empty list
The _parse_odds_html() method is a placeholder that always returns []. poll_odds() will succeed but store nothing until the parser is implemented. This is expected for Gap 8 — the interface and pipeline are in place.
src/data/scrapers/live_odds.py:96-99
11. Gemini model hardcoded to gemini-2.5-flash
gemini_fetcher.py hardcodes gemini-2.5-flash as the model name. Should be configurable via environment variable or settings for model upgrades.
src/data/gemini_fetcher.py (model constant)
12. Exotic engine still uses compute_superfecta_for_anchor (3D ndarray)
Gap 1 changed SimulationResult.superfecta_probs to dict, but compute_superfecta_for_anchor() still returns its own 3D ndarray. This is correct — the anchor function computes a separate, focused array — but the two superfecta approaches (full dict vs anchor array) coexist without clear documentation of when to use which.
src/models/monte_carlo.py:157-198 vs SimulationResult.superfecta_probs
13. Pre-existing lint issues (28 warnings in untouched files)
28 ruff warnings exist in files not modified during the Gaps build. Mostly unused imports (F401), ambiguous variable l (E741), and unused local variables (F841). All new/modified files pass lint clean.
Various — run ruff check src/ tests/ for full list
14. BRIS field positions are brittle magic numbers
bris_parser.py maps ~100 fields at hardcoded column positions (e.g., bris_speed @ 210, PPs start @ 255). These are correct per the BRIS DRF spec, but a format change would silently produce wrong data. Consider adding a header validation check.
src/data/bris_parser.py (RACE_FIELDS, ENTRY_FIELDS, PP_BLOCK constants)
